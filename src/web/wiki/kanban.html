Kanban Board

The Kanban board is a ticket-management interface within SARAB that models work items through a six-column workflow. Tickets can be created, edited, moved, deleted, and run as Claude jobs. The board supports project filtering, subtickets with parent-child relationships, drag-and-drop reordering, and color-coded priority indicators.

Column Workflow

Every ticket belongs to exactly one of six columns, representing a linear workflow from ideation to completion:

ColumnPurpose
backlogUnsorted ideas and unplanned work. Default column for new tickets.
readyTriaged and ready to pick up. Has clear scope and acceptance criteria.
in-progressActively being worked on. A Claude job may be linked.
pausedBlocked or set aside. Can be resumed later without losing context.
testingAwaiting verification. Job output is being reviewed.
doneCompleted and verified. Terminal state.

Tickets are moved between columns via drag-and-drop on the board or through the Move action in the card toolbar. The /api/tickets/:id/move endpoint handles column transitions server-side.

Priorities

Each ticket carries a priority level displayed as a color-coded left border on the card. Priorities are set at creation time and can be changed on edit.

PriorityCSS ClassBorder Color
criticalprio-criticalRed
highprio-highOrange
mediumprio-mediumYellow
lowprio-lowDim (gray)

The type definition is TicketPriority = "low" | "medium" | "high" | "critical", defined in src/queue/types.ts.

Ticket CRUD

Create

The "New Ticket" button opens a form modal with fields for title, description (markdown), priority, column, project association, and tags. Subtickets can be created from a parent card via the "+Sub" button, which pre-populates the parentId. The POST payload is sent to /api/tickets. On success the board refreshes via SSE.

Edit

The "Edit" button on each card opens a pre-filled form modal. Changes are sent via PATCH to /api/tickets/:id. All fields except id are mutable.

Move

Tickets are moved by dragging a card and dropping it onto a different column. The drop handler calls POST /api/tickets/:id/move with the target column name. A "Move" button is also provided in the card toolbar as a fallback when drag-and-drop is impractical.

Delete

"Del" sends DELETE /api/tickets/:id. The server cascades deletion to all subtickets (children with matching parentId) and cleans up any linked markdown files. A confirmation step is handled on the frontend before the request is sent.

Run

"Run" converts a ticket into a Claude job. The frontend sends a POST to /api/jobs with the ticket's title as the job title and the description as the prompt. The resulting jobId is patched back onto the ticket via PATCH /api/tickets/:id. The ticket card then displays a clickable "Job: <id>" badge linking to the job in the queue view. The job is also tagged with "kanban" for traceability.

Subtickets

Subtickets implement a parent-child hierarchy via the parentId field on each ticket:

  • Parent reference: A subticket's parentId is set to the parent ticket's id.
  • Badge display: Parent cards show a count badge (e.g., "3 sub") in the meta section.
  • Indented children: Subtickets are rendered below the parent card, visually indented with a left border accent. Each subticket is itself a draggable card with its own action toolbar.
  • Child tag: Subticket cards display a "Child" tag so they are distinguishable from top-level tickets.
  • +Sub button: Opens a modal with parentId pre-filled. The form otherwise behaves identically to a top-level ticket create.
  • Cascade delete: Deleting a parent ticket deletes all its subtickets.

The frontend renders subtickets by filtering tickets.filter(st => st.parentId === t.id) at render time. There is no depth limit, but the UI only indents one level.

Markdown Persistence Format

Tickets are stored as both JSONL (cache) and individual markdown files under the project directory. The markdown format is human-readable and version-controlled alongside the project code.

File Location

<projects-root>/<project-slug>/tickets/<column>/<slugified-title>-<8char-id>.md

Format

Title: Implement user authentication
Kanban Status: in-progress
Priority: high
Project: proj_abc123
Parent:
Job: job_xyz789
Session:
Tags: auth, security
Created: 2026-05-09T10:00:00.000Z
Updated: 2026-05-09T14:30:00.000Z
Started: 2026-05-09T10:05:00.000Z
Paused:
Done:
Ticket ID: a1b2c3d4
========================================
Content:
## Acceptance Criteria
- [ ] User can register with email + password
- [ ] User can log in
- [ ] Session tokens expire after 24 hours

## Notes
Uses JWT stored in httpOnly cookies.

The markdown header uses Key: Value lines terminated by a === divider. The Content: section holds the free-form markdown description. Serialization and deserialization are handled by src/storage/md-serializer.ts.

Project Filtering

A project filter dropdown sits at the top of the board. When a project is selected, only tickets with a matching projectId are displayed. The filter value is stored in the kanbanProjectId global variable and passed as a query parameter to GET /api/tickets?projectId=.... Setting the filter to "All Projects" clears the parameter and returns every ticket.

Run Ticket Flow (detailed)

User clicks "Run" on ticket
  → POST /api/jobs { title, prompt: t.description, projectId, tags: [..., "kanban"] }
  → Server creates Job, returns { id: "job_xxx" }
  → PATCH /api/tickets/:id { jobId: "job_xxx" }
  → Board refreshes, card shows "Job: job_xxx" badge
  → QueueManager picks up the job, executor spawns claude CLI
  → Job output streams via SSE; ticket remains on board

The prompt sent to Claude is the ticket's description field (markdown content), falling back to the title. The resulting job is linked bidirectionally: the ticket stores jobId, and the job can be inspected from the queue view via the badge link.

Frontend Module

The Kanban board is implemented in src/web/js/views/kanban.js as a vanilla JS view within the SARAB single-page application. Key functions:

  • loadTickets() — fetches tickets from /api/tickets with optional project filter.
  • renderKanban() — builds the board DOM: column headers with ticket counts, card grids, drag-drop zones, project filter, and action buttons.
  • renderTicketCard(t) — renders a single card with priority border, title, description excerpt, meta tags, action buttons, and indented subtickets.
  • showTicketForm() / showEditTicketForm(id) — modal create and edit forms.
  • showSubticketForm(parentId) — modal for creating a child ticket.
  • bindTicketActions() — wires edit, run, subticket, and delete button handlers.
  • bindKanbanDrag() — sets up HTML drag-and-drop on .kanban-card elements with column drop zones.

The board data is polled via the shared SSE connection, which emits update events that trigger a loadTickets() + renderKanban() cycle.
