Settings & Providers

Settings are stored in data/settings.json as a single JSON file. The SettingsStore handles load, save, and validation. The frontend Settings view (js/views/settings.js) exposes provider management and execution defaults through PUT /api/settings.

AI Providers

SARAB supports two provider types:

TypeValueExecutorDescription
Claude CLI"claude-cli"ClaudeExecutorSpawns claude -p "prompt" locally. Configured via claudeCmd and claudeFlags.
OpenAI-compatible"openai-compatible"DeepSeekExecutorHTTP POST to any OpenAI-compatible API (DeepSeek, OpenAI, etc.). Configured via baseUrl and apiKeyEnvVar.

Provider Fields

{
  "id": "claude-cli-default",        // Auto-generated, 8-char UUID
  "name": "Claude CLI",              // Human-readable, must be unique
  "type": "claude-cli",              // "claude-cli" | "openai-compatible"
  "apiKeyEnvVar": "ANTHROPIC_AUTH_TOKEN", // Environment variable name
  "defaultModel": "claude-sonnet-4-6",    // Default model for this provider
  "enabled": true,                   // Toggle on/off
  "isDefault": false,                // Only one provider can be default
  "baseUrl": "",                     // Base URL for openai-compatible types
  "claudeCmd": "claude",             // CLI command (claude-cli only)
  "claudeFlags": "--dangerously-skip-permissions" // Extra flags (claude-cli only)
}

Execution Defaults

These apply to every new job unless overridden per-job:

{
  "executionDefaults": {
    "timeoutMs": 0,            // 0 = no hard timeout (unlimited)
    "idleTimeoutMs": 1800000,  // 30 min — kill if no output received
    "maxRetries": 2            // Retry attempts on failure before giving up
  }
}
  • timeoutMs — Hard wall-clock timeout. 0 means run forever (until completion or idle timeout).
  • idleTimeoutMs — Kills the process if no stdout/stderr output for this duration. The heartbeat monitor in ClaudeExecutor tracks this.
  • maxRetries — Number of automatic retries when a job fails. The queue manager increments attempt and re-queues.

Prompt Improvement Settings

The prompt improvement feature (reformulate, shorten, expand, correct, improve) uses a dedicated AI provider:

{
  "promptImprovement": {
    "providerId": "claude-cli-default",  // Which provider to use
    "model": "claude-sonnet-4-6"         // Model for improvement calls
  }
}

Endpoints: POST /api/prompt/reformulate, /improve, /correct, /shorten, /expand.

Validation and Fallback

The SettingsStore.load() method applies two safety mechanisms:

  • Deep-merge with defaults — Any missing keys in executionDefaults or promptImprovement are filled from the baked-in defaults. New config keys (added in future versions) never break existing settings files.
  • Stale defaultProviderId recovery — If the saved defaultProviderId does not match any provider in the list, it is automatically reset to the first enabled provider (or the first provider overall) and a warning is logged.
The PUT /api/settings endpoint also rejects a request where defaultProviderId is not found in the submitted providers array — returns ValidationError with 400 status.

Per-Project Settings

Projects can override execution defaults via the settings field in project.json:

{
  "settings": {
    "defaultModel": "claude-sonnet-4-6",
    "defaultExecutionMode": "api",       // "api" | "terminal"
    "defaultSessionMode": "resume",      // "new" | "resume" | "latest"
    "templates": {
      "reformulate": "Rewrite this prompt...",
      "ticketSplit": "Split the following into tickets...",
      "implementation": "Implement the following...",
      "test": "Write tests for...",
      "reflection": "Reflect on..."
    }
  }
}

Template strings are used by the chatbot and prompt improvement features to provide project-specific context when generating prompts.
