Run Playwright tests with:

# All Playwright tests (API + UI)
npx playwright test

# Specific file
npx playwright test tests/api.spec.ts
npx playwright test tests/ui.spec.ts

# With UI mode (interactive)
npx playwright test --ui

The Playwright config in playwright.config.ts auto-starts the dev server on port 3469 via webServer. Two workers can conflict on JSONL writes, so tests use 1 worker (workers: 1). Each describe block cleans up its own data (cancel + delete jobs, delete projects).

Smoke Tests

The scripts/smoke-test.sh script starts a fresh dev server on a specified port, runs 16 curl-based API checks, then shuts it down. It covers health, static files, job CRUD, queue pause/resume, cancel, delete, and SSE connectivity.

Each smoke test run uses a separate port to avoid conflicting with a running dev server:

./scripts/smoke-test.sh           # Port 3457
./scripts/smoke-test.sh 3467      # Custom port

Running Everything

# Full test suite (JS syntax check + TypeScript + smoke + Playwright)
./scripts/run-all-tests.sh

# Individual components
npm run test:unit                   # 24 unit tests
npm run check                       # tsc --noEmit
npx playwright test                 # 100 Playwright tests (API + UI)
./scripts/smoke-test.sh 3467        # 16 curl checks on port 3467

Test Conventions

  • Clean data before run: Each test block creates its own fixtures and cleans up via afterEach / afterAll. Tests should never depend on state left by another test.
  • 1 Playwright worker: JSONL writes use atomic temp files (uuid-tmp naming), but parallel workers can still conflict. The config sets workers: 1.
  • Separate port per smoke test: Smoke tests start their own server. Pass PORT via env or first argument to avoid clashing with a running instance.
  • Queue paused during Job CRUD tests: Job CRUD tests pause the queue via POST /api/queue/pause so created jobs stay pending and can be cancelled/deleted without racing the poll loop.
  • SSE curl timeout: Always use --max-time 2 when curling SSE endpoints — they never close on their own.

JS Syntax Check

The run-all-tests.sh script runs node -c on every file under src/web/js/ before executing any tests. This catches accidental TypeScript syntax (e.g., : any annotations) in vanilla JS files. Run it manually:

for f in src/web/js/*.js src/web/js/views/*.js; do
  node -c "$f"
done
The frontend is plain vanilla JS — no TypeScript, no bundler, no framework. Never use TypeScript annotations (: any, : string, etc.) in src/web/ files. The node -c check will reject them.
